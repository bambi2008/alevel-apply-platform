# 考试可靠性与断点续考

## 目标

全站考试运行器遵守同一组可靠性约束：

- 刷新或意外关闭页面后，学生可以恢复未完成考试。
- 浏览器进入后台或设备卡顿时，考试计时仍以固定截止时间为准。
- 网络断开时答案继续保存在本机，界面明确提示离线状态。
- 考试进行中离开页面会触发浏览器保护提示。
- 同一次考试的重复提交只生成一条历史记录。

## 本地快照协议

统一快照使用 `ExamAttemptSnapshot` v2，包含：

- `attemptId`：由考试、卷型和开始时间生成的稳定标识。
- `runner`：`objective`、`written` 或 `mixed`。
- `testId` 与 `scopeId`：验证快照是否属于当前考试。
- `startedAt` 与 `deadlineAt`：恢复真实计时，不因关闭页面暂停。
- `payload`：题目顺序、当前位置、答案和运行器特有状态。

快照保存在浏览器 `localStorage`，有效期最长七天。过期、已到截止时间、结构损坏或考试范围不匹配的快照不会恢复。交卷或学生主动放弃进度后立即清除。

随机模拟卷会保存本次抽题的题目 ID。恢复时按原顺序重建试卷，不重新抽题。

## 离线与离开保护

考试运行中监听浏览器在线状态。离线时显示固定提示，答题仍写入本地快照；提交需要恢复网络。运行中关闭、刷新或跳转页面时启用 `beforeunload` 保护。

本地快照可能包含学生答案。公用设备上的学生应在完成后交卷或主动放弃旧进度；平台不会把未提交快照跨设备同步。

## 提交幂等

客户端提交考试历史时携带稳定 `attemptId`。服务端在创建记录前，按学生、考试、开始时间、固定卷或模拟预设查询已有记录；网络重试或重复点击会返回已有会话 ID。

当前实现是应用层幂等，适合单实例和常规重试。未来若需要高并发多实例提交，应为数据库增加独立、唯一的 `attemptId` 列并执行迁移。

## 验收清单

- 客观题：作答、刷新、继续，题目位置和答案保持一致。
- 书面卷：输入长答案、刷新、继续，文本完整恢复。
- 随机模拟：刷新后题目集合和顺序不变。
- 后台停留后返回：剩余时间按真实经过时间扣减。
- 离线：出现提示，继续作答后刷新仍可恢复。
- 交卷：快照清除，重复提交不新增考试历史。
- 桌面端与手机端：恢复提示、离线提示和考试工具栏无横向溢出。

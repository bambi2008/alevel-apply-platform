# 错题复测与风险清零

## 目标

把“做过错题”升级为可验证的修复过程。系统不因一次重做答对就宣布掌握，而是记录每道失分题从待修复、恢复、稳定到复发的证据轨迹。

## 状态规则

| 状态 | 判定 |
| --- | --- |
| 已排期 | 最近得分低于 80%，尚未到下一次复测时间 |
| 待复测 | 最近得分低于 80%，已到复测时间 |
| 已恢复 | 失分后再次达到 80%，但稳定性证据不足 |
| 已稳定 | 至少在两个不同日期连续达到 80%，且成功记录间隔不少于 3 天 |
| 复发 | 曾经恢复后再次低于 80% |

低于 50% 的题目次日复测，50%–79% 的题目三天后复测。首次恢复三天后确认稳定，已稳定题目十天后进入保温复习。

## 定向选题

复测训练按以下顺序选题：

1. 专项题库中可直接重做的复发题和到期题；
2. 同一知识点、匹配难度的变式题；
3. 固定套卷失分但不在专项题库时，自动回退到同主题变式题。

因此固定卷中的问题不会生成无法打开的复测入口。

## 就绪度联动

考试就绪度会读取修复画像。存在复发题，或待复测问题大量堆积时，考前冲刺中心显示独立风险门槛；三道及以上复发题属于阻断风险。风险不会因为点击任务或完成任意练习而清除，只会随新的作答证据重新计算。

## 路由

- 学生工作台：`/[locale]/tests/[testId]/review`
- 画像接口：`/api/exam-sessions/remediation?testId=[testId]`
- 定向训练：`/[locale]/tests/[testId]/practice?adaptive=1&remediation=1`

本工程复用 `ExamSession` 与 `ExamAnswer`，不新增数据库迁移。

## 发布检查

```powershell
pnpm test
pnpm audit:questions
pnpm build
```

网页验收覆盖空状态、待修复状态、桌面端和 390px 手机端，并检查复测按钮、同类强化链接、顶部导航和横向溢出。
